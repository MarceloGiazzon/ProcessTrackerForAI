    Manual do ptrack

    Como ver e controlar os programas demorados que você ou o seu agente de IA deixam rodando no computador. Escrito para quem não é especialista.

    O que é o ptrack

    O ptrack é um pequeno programa de linha de comando que funciona como uma torre de controle para tarefas demoradas: compilações, testes, servidores, downloads, instalações.

    Hoje é comum pedir a um agente de IA (Claude Code, Codex, Cursor, Gemini CLI, Aider…) que rode um comando que leva vários minutos. Depois surgem as dúvidas: ainda está rodando? Travou? Terminou bem? Quem iniciou isso? Sem uma ferramenta, o agente precisa ler logs enormes para responder, e isso gasta tempo e dinheiro (tokens).

    Com o ptrack, cada comando vira um job (uma tarefa registrada). Você vê todos numa lista, sem gastar nada, e pode parar, pausar, retomar ou rodar de novo qualquer um deles.

    O que ele promete

    • Um único arquivo, nada para instalar. Menos de 1 MB. Não precisa de banco de dados nem de serviço rodando em segundo plano.
    • Funciona no Windows, Linux e macOS, com o mesmo cuidado nos três.
    • Funciona com qualquer agente e com qualquer projeto. Também serve para você, sem agente nenhum.
    • Estados honestos. Se algo deu errado sem aviso, ele mostra isso. Nunca diz que algo “passou” quando não sabe.
    • Para tudo de uma vez. Ao parar um job, ele para também todos os programas que esse job abriu.
    • Só no seu computador. Sem conta, sem internet, sem coleta de dados. (A única exceção é o webhook, que só funciona se você mesmo configurar.)

    Conceitos básicos

    Cinco ideias bastam para usar o ptrack com segurança.

    Terminal

    É a janela onde se digitam comandos. No Windows, abra o PowerShell (procure “PowerShell” no menu Iniciar). No macOS, abra o app Terminal. No Linux, o terminal do seu sistema. Todos os comandos deste manual são digitados ali, seguidos de Enter.

    Job

    Um job é um comando que o ptrack está acompanhando. Cada job tem:

    • um ID, um código curto de 6 letras e números, como k3f9a2;
    • um nome opcional (rótulo), como “build completo”;
    • a pasta onde rodou, quem iniciou (você ou qual agente), quando começou e quanto tempo levou;
    • a saída do comando (tudo o que ele escreveu na tela), guardada num arquivo de log.

    Não é preciso digitar o ID inteiro: as primeiras letras bastam, desde que não haja outro job começando igual. A palavra last significa “o job mais recente”.

    Estados de um job

    EstadoO que significa
    runningEstá rodando agora.
    pausedFoi congelado. Não usa processador, mas continua na memória e pode ser retomado.
    passedTerminou com sucesso (código de saída 0).
    failedTerminou com erro (código de saída diferente de 0).
    cancelledAlguém parou o job de propósito, com ptrack stop ou pelo painel.
    lostPerdido. O ptrack que vigiava o job sumiu sem avisar (o computador desligou, a janela foi fechada à força…). O resultado real é desconhecido, por isso ele não finge que passou.

    Código de saída

    Todo programa, ao terminar, devolve um número: 0 quer dizer “deu certo” e qualquer outro número quer dizer “deu errado”. O ptrack guarda esse número e devolve o mesmo, para que scripts e agentes saibam o resultado.

    Supervisor

    Quando você roda um comando pelo ptrack, uma cópia do ptrack fica “de babá” daquele comando: guarda a saída, anota a cada 2 segundos que o job continua vivo e registra o resultado no final. Esse vigia é o supervisor. Se ele parar de dar sinal por mais de 10 segundos e não existir mais, o job aparece como lost.

    Instalação

    Escolha o seu sistema, copie a linha e cole no terminal.

    Abra o PowerShell e rode:

    irm https://raw.githubusercontent.com/MarceloGiazzon/ProcessTrackerForAI/main/install.ps1 | iex

    O programa vai para %LOCALAPPDATA%\Programs\ptrack e essa pasta é adicionada ao PATH, a lista de pastas onde o sistema procura comandos. Feche e abra o terminal de novo depois de instalar.

    Abra o Terminal e rode:

    curl -fsSL https://raw.githubusercontent.com/MarceloGiazzon/ProcessTrackerForAI/main/install.sh | sh

    O programa vai para ~/.local/bin. Se essa pasta ainda não estiver no PATH, o instalador mostra a linha exata que você precisa adicionar.

    Conferir se funcionou

    ptrack version

    Se aparecer um número de versão, está tudo certo. Se aparecer “comando não encontrado”, veja Solução de problemas.

    Atualizar

    Rode o mesmo comando de instalação de novo. Ele baixa a versão mais recente e confere a integridade do arquivo (checksum) antes de instalar.

    Outras formas

    Você também pode baixar o arquivo do seu sistema na página Releases do projeto no GitHub, ou compilar a partir do código com cargo install --path . se tiver Rust instalado.

    Primeiros passos

    Um passeio de cinco minutos. Os exemplos usam npm test e gradle build, mas vale qualquer comando que você já usa.

    Antes de começar: entre na pasta do projeto

    O ptrack roda o comando exatamente como você rodaria sem ele. Por isso, npm test só funciona dentro da pasta do projeto (a que tem o arquivo package.json), e gradle build só funciona se o Gradle estiver instalado. Se o comando falharia sem o ptrack, também falha com ele. Primeiro vá para a pasta do projeto, por exemplo:

    cd C:\Projetos\NPDev

    Para um teste que funciona em qualquer pasta, use ptrack run -s -- "echo olá".

    1. Rode um comando pelo ptrack. Basta colocar ptrack run -- na frente. A saída aparece na tela normalmente.

      ptrack run -- npm test

      Os dois tracinhos -- separam as opções do ptrack do comando que você quer rodar.

    2. Rode algo demorado em segundo plano e receba o terminal de volta na hora:

      ptrack run -d -l "build completo" -- gradle build

      Ele responde algo como job k3f9a2 started in background. Anote o ID.

    3. Veja o que está rodando:

      ptrack list
      ID      STATE       TIME   STARTED   PROJECT   TAG       AGENT        WHAT            LAST LINE
k3f9a2  running    3m04s  3m04s ago NPDev     CI Watch  claude-code  build completo  > Task :app:compileJava
x9ewes  passed       41s    12m ago NPDev     -         claude-code  npm test        Tests: 212 passed
cexj44  failed        2s     1h ago website   -         -            ./deploy.sh     error: missing API_URL

      A coluna PROJECT mostra a qual projeto o job pertence e TAG mostra a etiqueta, se houver (veja Projetos e etiquetas). A última coluna mostra a última linha que cada job escreveu, o que muitas vezes já basta para saber como ele está.

    4. Acompanhe a saída ao vivo (Ctrl+C para sair da visualização; o job continua rodando):

      ptrack tail k3f9a2 -f

    5. Pare o job, junto com tudo o que ele abriu:

      ptrack stop k3f9a2

    6. Abra o painel no navegador para ver tudo com botões:

      ptrack ui

    Comandos do dia a dia

    Em todos os comandos, ID pode ser só o começo do código do job, ou last para o mais recente.

    ptrack run: rodar um comando como job

    ptrack run [opções] -- <comando>
    OpçãoPara que serve
    -l "texto"Dá um nome legível ao job, como “testes de integração”.
    -dRoda em segundo plano e devolve o terminal imediatamente.
    -qModo silencioso: não mostra a saída, só uma linha de resumo no final (e as últimas linhas se falhar).
    -sPassa o comando pelo shell do sistema. Necessário para usar &&, | (pipe) e afins.
    --project NOMEDiz a qual projeto o job pertence. Normalmente é descoberto sozinho.
    --tag "texto"Coloca uma etiqueta no job, como “CI Watch”.
    --agent NOMEDiz quem iniciou o job. Normalmente é detectado sozinho.
    --session IDIdentifica a sessão do agente. Normalmente é detectado sozinho.

    Exemplo com o shell, para encadear dois comandos:

    ptrack run -s -l "instalar e testar" -- "npm install && npm test"
    Sem teclado

    Jobs não recebem o que você digita. Um comando que faz perguntas (“Deseja continuar? s/n”) recebe “fim de entrada” em vez de ficar esperando para sempre. Use as opções do próprio programa para responder sim automaticamente, como -y ou --yes.

    ptrack list: o que está rodando e o que rodou

    ptrack list           # jobs ativos e recentes
ptrack list --all     # inclui os antigos
ptrack list --here    # só os iniciados nesta pasta
ptrack list --project NPDev        # só os deste projeto
ptrack list --tag "CI Watch"       # só os com esta etiqueta

    ptrack status: tudo sobre um job

    ptrack status k3f9a2

    Sem ID, mostra o job mais recente. Mostra o comando, a pasta, os horários, o estado, o código de saída e a última linha.

    ptrack tail: ver a saída

    ptrack tail k3f9a2          # últimas linhas
ptrack tail k3f9a2 -n 100   # últimas 100 linhas
ptrack tail k3f9a2 -f       # continua mostrando até o job acabar

    ptrack wait: esperar terminar

    ptrack wait k3f9a2 --timeout 600

    Fica esperando até o job acabar e sai com o mesmo código de saída do job. Se o tempo limite (em segundos) passar antes, sai com o código 124. Se o job falhar, mostra as últimas 20 linhas para você ver o erro.

    ptrack stop: parar

    ptrack stop k3f9a2              # pede com educação, força depois de 5 s
ptrack stop k3f9a2 --grace 30   # espera até 30 s antes de forçar
ptrack stop k3f9a2 --force      # encerra na hora

    Primeiro o ptrack pede ao programa que encerre (assim ele pode salvar o que precisa). Se o programa não sair dentro do tempo de espera, o ptrack encerra à força ele e todos os programas que ele abriu.

    ptrack pause / resume: congelar e descongelar

    ptrack pause k3f9a2
ptrack resume k3f9a2
    Pausar nem sempre é seguro

    Enquanto está congelado, conexões de rede e temporizadores podem expirar. Servidores e ferramentas Java (Gradle, Maven) às vezes não voltam bem. Para esses, prefira parar e rodar de novo.

    ptrack rerun: rodar de novo

    ptrack rerun k3f9a2        # na frente, como run
ptrack rerun k3f9a2 -d     # em segundo plano

    Repete o mesmo comando, na mesma pasta, como um job novo ligado ao antigo. Só funciona com jobs que já terminaram, porque duas cópias do mesmo build ou servidor na mesma pasta costumam brigar entre si.

    ptrack prune: faxina

    ptrack prune             # apaga jobs terminados há mais de 7 dias
ptrack prune --days 1    # há mais de 1 dia
ptrack prune --all       # todos os terminados

    Apaga o registro e o log dos jobs que já terminaram. Jobs que ainda estão rodando nunca são apagados.

    Projetos e etiquetas

    Quando você trabalha em vários projetos ao mesmo tempo, a lista mistura jobs de todos eles. Projetos e etiquetas ajudam a separar.

    Projeto

    Todo job pertence a um projeto, mostrado na coluna PROJECT. O ptrack descobre o nome sozinho:

    • se o comando rodou dentro de um repositório git, o projeto é o nome da pasta do repositório. Um job iniciado em NPDev\src\app pertence a NPDev;
    • fora de um repositório, é o nome da pasta atual.

    Para escolher outro nome, use --project:

    ptrack run --project NPDev -- npm test

    Etiqueta (tag)

    A etiqueta é opcional e livre: uma palavra ou frase curta para agrupar jobs parecidos, mesmo de projetos diferentes. Exemplos: CI Watch, nightly, release.

    ptrack run -d --tag "CI Watch" -- gh run watch 1234

    Filtrar

    ptrack list --project NPDev       # só os jobs do NPDev
ptrack list --tag "ci watch"      # maiúsculas e minúsculas tanto faz

    Definir para uma sessão inteira

    Para não repetir a opção em todo comando, defina uma variável de ambiente. Todos os jobs iniciados naquele terminal recebem o valor.

    $env:PTRACK_TAG = "CI Watch"        # PowerShell (Windows)
export PTRACK_TAG="CI Watch"        # macOS e Linux

    Para o projeto, a variável é PTRACK_PROJECT. O ptrack rerun mantém o projeto e a etiqueta do job original. O painel mostra os dois em cada job, e o servidor MCP permite que o agente filtre por eles.

    Painel no navegador

    Para quem prefere botões a comandos:

    ptrack ui

    Abre uma página no seu navegador com todos os jobs, atualizada ao vivo. Nela você pode:

    • clicar num job para ver a saída dele;
    • usar os botões Pause, Resume e Stop;
    • usar o botão Rerun num job terminado para rodá-lo de novo na mesma pasta;
    • escolher um projeto ou uma etiqueta nos menus do topo (All projects, All tags) para ver só esses jobs. A página lembra a sua escolha;
    • marcar Show older jobs para ver também os antigos;
    • marcar Notify when jobs end para receber um aviso do navegador quando um job terminar. Funciona só enquanto a página estiver aberta. Na primeira vez, o navegador pede permissão.

    No topo aparece quantos jobs estão rodando e se a página está live (conectada) ou offline (o ptrack ui foi fechado).

    Segurança do painel

    A página só pode ser aberta do seu próprio computador. O endereço contém uma chave aleatória, que muda toda vez que você roda ptrack ui. Para fechar o painel, volte ao terminal e aperte Ctrl+C.

    ptrack ui --port 8765    # usar uma porta fixa
ptrack ui --no-open      # não abrir o navegador sozinho (o endereço aparece no terminal)

    Avisos quando um job termina

    Assim você pode largar o computador e ser avisado quando o build acabar.

    Notificação na área de trabalho

    ptrack notify on      # liga (vem desligado)
ptrack notify test    # manda uma notificação de teste agora
ptrack notify         # mostra a configuração atual
ptrack notify off     # desliga

    Para não incomodar, só avisam os jobs que rodaram pelo menos 30 segundos. Jobs que você mesmo parou não avisam, porque você já sabe. Para mudar o mínimo:

    ptrack notify min-seconds 120

    O ptrack usa o que o sistema já tem: no Windows a notificação aparece como vinda do “Windows PowerShell”; no macOS usa o osascript; no Linux usa o notify-send. No Ubuntu, se o notify-send faltar, instale com sudo apt install libnotify-bin.

    Aviso no celular ou no chat (webhook)

    Um webhook é um endereço da internet que recebe mensagens automáticas. Com ele, o ptrack manda um aviso para o Slack, o Discord ou o app ntfy no celular sempre que um job termina.

    ptrack notify webhook https://hooks.slack.com/services/...   # Slack ou Discord
ptrack notify test                                           # manda um teste
ptrack notify webhook off                                    # desliga

    No celular, com o app gratuito ntfy:

    1. Instale o app ntfy no celular e assine um tópico com um nome difícil de adivinhar, por exemplo meus-builds-x7q2.

    2. No computador, configure o ptrack para mandar texto simples a esse tópico:

      ptrack notify webhook https://ntfy.sh/meus-builds-x7q2
ptrack notify webhook-format text

    3. Teste com ptrack notify test. O aviso deve chegar no celular.

    Cuidado com o que é enviado

    A mensagem leva o comando e a última linha da saída. Só use um serviço em que você confia. No ntfy público, qualquer pessoa que souber o nome do tópico pode ler as mensagens, por isso escolha um nome difícil de adivinhar.

    Para quem usa scripts: no formato padrão (JSON) a mensagem tem os campos text (lido pelo Slack), content (lido pelo Discord) e job (o registro completo do job). O endereço precisa começar com http:// ou https://. O envio usa o curl, que já vem no Windows 10 ou mais novo, no macOS e no Linux.

    Usar com agentes de IA

    Há três formas, da mais simples à mais automática. Dá para combinar.

    1. Dar instruções ao agente

    Funciona com qualquer agente. O comando ptrack instructions mostra o texto certo, e você pode acrescentá-lo direto ao arquivo de instruções do agente:

    ptrack instructions | Add-Content AGENTS.md    # PowerShell (Windows)
ptrack instructions >> AGENTS.md               # macOS e Linux

    Troque AGENTS.md pelo arquivo que o seu agente lê (veja a tabela em Receitas por agente). O texto é este:

    ## Long-running commands
Run any command that may take more than ~30 seconds (builds, test suites, servers, downloads,
migrations) through `ptrack`:
- In the background: `ptrack run -d -l "<short label>" -- <command>`. It prints a job id.
- To check progress cheaply: `ptrack status <id>` or `ptrack list`. They show the state and the
  last output line, so there is no need to read the log.
- To wait for the result: `ptrack wait <id> --timeout 600`. It exits with the job's exit code and
  prints the last 20 lines only if the job failed.
- In the foreground with little output: `ptrack run -q -- <command>`. It prints one summary line,
  plus the last lines on failure.
- To stop a job: `ptrack stop <id>`.
- Add `--tag "<tag>"` to group related jobs; `ptrack list --tag "<tag>"` shows only those.

    O texto está em inglês de propósito: é o idioma que os agentes seguem com mais precisão.

    2. Servidor MCP

    MCP é um padrão que permite ao agente “conversar” com ferramentas. Com ele, o agente consulta os jobs numa única chamada curta, sem ler logs.

    No Claude Code:

    claude mcp add --scope user ptrack -- ptrack mcp

    Em outros clientes (Cursor, Gemini CLI…), adicione ao arquivo de configuração MCP:

    { "mcpServers": { "ptrack": { "command": "ptrack", "args": ["mcp"] } } }

    Por padrão o agente só pode olhar: listar (inclusive filtrando por projeto ou etiqueta), ver status, ver saída e esperar. Para deixá-lo também parar, pausar, retomar e rodar de novo, use ptrack mcp --allow-control. Iniciar comandos novos continua sendo feito pelo terminal, de propósito.

    3. Gancho automático no Claude Code

    Com o gancho (hook), você não depende de o agente se lembrar de usar o ptrack. Os comandos demorados passam por ele sozinhos.

    ptrack hook install            # para todos os seus projetos
ptrack hook install --project  # só para o projeto atual

    Reinicie o Claude Code depois de instalar. A partir daí:

    • Comandos demorados (builds, testes, instalações, servidores, Docker…) e todo comando em segundo plano viram jobs automaticamente. O Claude vê a mesma saída de antes, com uma linha [ptrack] no início e outra no fim.
    • Cada job recebe como nome a descrição que o Claude deu ao comando, e fica ligado à sessão e ao pedido que o originou. Uma prévia de até 200 caracteres de cada pedido fica guardada no seu computador. Use --no-prompts se não quiser isso.
    • --all faz todos os comandos passarem pelo ptrack, não só os demorados.

    Para desfazer:

    ptrack hook uninstall            # ou: ptrack hook uninstall --project

    Suas outras configurações são mantidas, e uma cópia de segurança é salva ao lado do arquivo de configurações.

    Efeito nas permissões

    O gancho nunca aprova nada sozinho. Mas como o comando é reescrito, uma regra de permissão como Bash(npm test:*) deixa de combinar com o npm test embrulhado. No modo de permissão padrão, o Claude Code vai pedir sua confirmação antes de rodar. O modo automático e o modo sem confirmação não são afetados.

    Quem iniciou cada job

    O ptrack reconhece sozinho Claude Code, Codex, Cursor, Antigravity CLI e Gemini CLI, e mostra o nome na coluna AGENT. No Claude Code e no Codex ele também guarda a sessão. Para outros agentes (o Aider, por exemplo), use --agent e --session, ou defina as variáveis de ambiente PTRACK_AGENT e PTRACK_SESSION.

    Receitas por agente

    Como configurar o ptrack em cada agente. O passo das instruções é o mais importante; o MCP é um bônus.

    AgenteArquivo de instruçõesMCPReconhecido sozinho
    Claude CodeCLAUDE.mdclaude mcp addSim, com sessão (e o gancho)
    CodexAGENTS.mdcodex mcp addSim, com sessão

    Gemini CLIGEMINI.mdgemini mcp addSim

    Codex

    ptrack instructions | Add-Content AGENTS.md
codex mcp add ptrack -- ptrack mcp

    Se o Codex estiver no modo protegido (sandbox) e não puder gravar fora da pasta do projeto, guarde os dados do ptrack dentro do projeto com PTRACK_HOME=.ptrack e coloque .ptrack/ no .gitignore.

    Cursor

    ptrack instructions | Add-Content AGENTS.md

    Para o MCP, crie o arquivo .cursor/mcp.json na pasta do projeto (ou ~/.cursor/mcp.json para todos os projetos):

    { "mcpServers": { "ptrack": { "type": "stdio", "command": "ptrack", "args": ["mcp"] } } }

    Antigravity CLI e Gemini CLI

    Em junho de 2026 o Google substituiu o Gemini CLI pelo Antigravity CLI (comando agy). No Antigravity CLI:

    ptrack instructions | Add-Content AGENTS.md

    Para o MCP, coloque isto em ~/.gemini/config/mcp_config.json (todos os projetos) ou .agents/mcp_config.json (só este projeto):

    { "mcpServers": { "ptrack": { "command": "ptrack", "args": ["mcp"] } } }

    Se você ainda usa o Gemini CLI:

    ptrack instructions | Add-Content GEMINI.md
gemini mcp add --scope user ptrack ptrack mcp

    Aider

    ptrack instructions | Add-Content CONVENTIONS.md

    Para o Aider ler esse arquivo sempre, adicione a linha read: CONVENTIONS.md ao arquivo .aider.conf.yml. O Aider não se identifica sozinho; para ver “aider” na coluna AGENT, abra-o assim:

    $env:PTRACK_AGENT = "aider"; aider     # PowerShell
PTRACK_AGENT=aider aider               # macOS e Linux

    Conferir se funcionou

    Peça ao agente algo demorado, como “rode os testes”, e depois rode ptrack list. O job deve aparecer com o nome do agente na coluna AGENT e o seu projeto na coluna PROJECT. Se AGENT mostrar -, o agente não se identificou: use PTRACK_AGENT como no Aider.

    Onde ficam os dados

    Tudo fica em arquivos comuns, numa pasta só sua:

    SistemaPasta
    Windows%LOCALAPPDATA%\ptrack
    Linux~/.local/share/ptrack
    macOS~/Library/Application Support/ptrack

    Dentro dela, jobs/<id>.json é a ficha de cada job (dá para abrir num editor de texto) e logs/<id>.log é a saída completa. Para usar outra pasta, defina a variável de ambiente PTRACK_HOME. Isso é útil para testes, porque não mistura com os seus jobs reais.

    Para scripts, ptrack list --json e ptrack status ID --json devolvem os dados em formato JSON.

    Senhas e segredos

    O comando e a saída são guardados como estão. Não passe senhas como parte do comando. Use variáveis de ambiente, que o ptrack nunca registra.

    Limites conhecidos

    • Parada educada no Windows. Muitos programas encerram quando recebem o pedido de parada (Ctrl+Break), mas alguns não. O Java imprime informações de depuração e o ping imprime estatísticas. Nesses casos o ptrack encerra à força quando o tempo de espera acaba.
    • Programas que se desligam de propósito podem escapar. Um programa que se separa do grupo de processos (como serviços do sistema fazem) deixa de ser alcançado por stop e pause. Ferramentas comuns de desenvolvimento não fazem isso.
    • Ajudantes em segundo plano continuam depois de um término normal. Por exemplo, o daemon do Gradle iniciado por um build continua rodando, como continuaria sem o ptrack. O stop encerra esses também.
    • Acentos no Windows. Programas que escrevem numa codificação antiga (como o ping num Windows em português) podem aparecer com letras acentuadas estranhas em tail e na última linha. O arquivo de log guarda os bytes originais.
    • Pausa: veja o aviso em ptrack pause.

    Solução de problemas

    “ptrack: comando não encontrado” / “não é reconhecido”

    Feche o terminal e abra outro: o PATH só é lido quando o terminal abre. No macOS e no Linux, confira se o instalador pediu para adicionar uma linha ao seu perfil do shell, e adicione.

    “npm error enoent Could not read package.json”

    Você rodou o comando fora da pasta do projeto. O npm procura o arquivo package.json na pasta atual. Entre na pasta do projeto com cd e rode de novo. O ptrack registra o job como failed, como deveria.

    “failed to start: could not start 'gradle': program not found”

    O programa não está instalado, ou não está no PATH. Teste sem o ptrack (só gradle --version): se também não funcionar, instale o programa primeiro. Muitos projetos trazem o próprio script: tente .\gradlew build (Windows) ou ./gradlew build (macOS e Linux) dentro da pasta do projeto.

    O código de saída é negativo, como -4058

    No Windows alguns programas (o npm, por exemplo) terminam com números negativos. É só outro código de erro. O job fica failed e o próprio ptrack sai com o código 1.

    O job aparece como lost

    O ptrack que vigiava o job sumiu: o computador reiniciou, o terminal foi fechado à força ou o processo foi encerrado de fora. Confira a saída com ptrack tail ID e, se precisar, rode de novo com ptrack rerun ID.

    Meu comando com && ou | não funciona

    Use a opção -s e coloque o comando inteiro entre aspas: ptrack run -s -- "a && b".

    O job ficou parado esperando uma resposta

    Jobs não recebem teclado. Use a opção do programa que responde “sim” automaticamente (-y, --yes, --non-interactive).

    A notificação não aparece

    Rode ptrack notify para conferir se está ligada, depois ptrack notify test. Lembre que só avisam jobs com pelo menos 30 segundos. No Windows, confira se as notificações do “Windows PowerShell” não estão bloqueadas nas configurações do sistema. No Linux, confira se o notify-send está instalado.

    O painel diz “offline”

    O ptrack ui foi fechado. Rode de novo e use o novo endereço, porque a chave muda a cada vez.

    O Claude Code passou a pedir confirmação para comandos que antes rodavam direto

    É o efeito do gancho nas regras de permissão (veja Gancho automático). Ajuste as regras ou use ptrack hook uninstall.

    Windows: “Acesso negado” ao atualizar o ptrack

    O Windows não deixa substituir um programa que está rodando. Pare os jobs em andamento (ptrack list, depois ptrack stop ID) e feche o ptrack ui antes de atualizar.

    Glossário

    Agente de IA
    Um assistente que escreve código e roda comandos por você, como Claude Code, Codex ou Cursor.
    Código de saída
    Número que um programa devolve ao terminar: 0 é sucesso, qualquer outro é erro.
    Daemon
    Programa que fica rodando em segundo plano, sem janela.
    Hook (gancho)
    Um ponto onde um programa deixa outro interferir. O ptrack usa o do Claude Code para embrulhar comandos.
    Job
    Um comando acompanhado pelo ptrack.
    Log
    Arquivo com tudo o que um comando escreveu na tela.
    MCP
    Model Context Protocol: um padrão para agentes de IA usarem ferramentas.
    PATH
    Lista de pastas onde o sistema procura os comandos que você digita.
    Projeto
    O conjunto de arquivos de um trabalho, normalmente uma pasta ou repositório git, como NPDev.
    Processo
    Um programa em execução. Um comando pode abrir vários.
    Segundo plano
    Rodar sem ocupar o terminal; você pode continuar digitando outras coisas.
    Shell
    O programa que interpreta o que você digita no terminal (cmd.exe, PowerShell, sh, bash…).
    Supervisor
    A cópia do ptrack que vigia um job do início ao fim.
    Tag (etiqueta)
    Palavra ou frase livre para agrupar jobs, como “CI Watch”.
    Token
    Unidade de texto pela qual agentes de IA são cobrados. Ler logs longos gasta muitos.
    Webhook
    Endereço da internet que recebe mensagens automáticas.
